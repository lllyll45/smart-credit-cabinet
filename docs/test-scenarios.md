# Тестовые сценарии — Smart Credit Cabinet

## 1. Назначение

Документ содержит ручные сценарии приёмочной проверки основного пользовательского пути, прав доступа, калькулятора, рекомендаций и обработки заявок сотрудником. Это план ручных проверок, а не утверждение, что каждый сценарий уже автоматизирован.

## 2. Подготовка

1. Запустить PostgreSQL и backend.
2. Применить миграции Alembic.
3. Заполнить каталог демонстрационными продуктами командой проекта `python -m scripts.seed_products` (из каталога `backend`, если модуль доступен в такой конфигурации).
4. Убедиться, что `/docs` и `/openapi.json` открываются.
5. Подготовить тестового клиента и пользователя с ролью `staff` или `admin`. Не назначать staff-роль через публичную регистрацию; использовать предусмотренный проектом административный способ.
6. Для каждого сценария использовать свежую тестовую заявку, если сценарий меняет её статус.

## 3. Сценарии

| ID | Сценарий | Действия | Ожидаемый результат |
|---|---|---|---|
| TC-01 | Регистрация | Отправить валидные `email` и пароль от 8 символов | Пользователь создаётся, пароль не хранится открытым текстом |
| TC-02 | Валидация регистрации | Отправить пароль короче 8 символов | Запрос отклонён валидацией |
| TC-03 | Повторный email | Зарегистрировать тот же email повторно | Дубликат не создаётся; API возвращает ошибку |
| TC-04 | Вход | Войти с корректными данными | Возвращается JWT |
| TC-05 | Неверный пароль | Войти с неправильным паролем | Доступ не предоставляется |
| TC-06 | Текущий пользователь | Вызвать `/auth/me` с валидным токеном | Возвращаются данные текущего пользователя |
| TC-07 | Нет токена | Вызвать защищённый endpoint без Bearer-токена | Возвращается 401/ошибка авторизации согласно контракту |
| TC-08 | Каталог | Вызвать `GET /products` | Возвращаются активные продукты |
| TC-09 | Детали продукта | Запросить существующий ID | Возвращаются данные продукта |
| TC-10 | Несуществующий продукт | Запросить неизвестный ID | Возвращается 404 согласно реализации |
| TC-11 | Расчёт платежа | Рассчитать платёж для допустимых продукта, суммы и срока | Возвращаются платёж, общая сумма и переплата |
| TC-12 | Недопустимая сумма | Рассчитать или отправить заявку с суммой вне диапазона продукта | Запрос отклоняется с понятной ошибкой |
| TC-13 | Сравнение | Вызвать `/calculator/compare` с суммой и сроком | Список подходящих продуктов отсортирован по общей сумме |
| TC-14 | Профиль бизнеса | Выполнить `PUT /business-profile`, затем `GET` | Профиль сохраняется и возвращается |
| TC-15 | Неверная организационная форма | Передать `legal_form`, отличный от `IP`/`OOO` | Валидация отклоняет запрос |
| TC-16 | Создание заявки | Создать заявку с валидными полями | Создаётся заявка в статусе `draft` |
| TC-17 | Редактирование черновика | Изменить заявку в `draft` через PATCH | Изменения сохранены |
| TC-18 | Редактирование отправленной заявки | Попробовать изменить `submitted` | Изменение запрещено |
| TC-19 | Отправка заявки | Отправить черновик через `/submit` | Статус `submitted`, вычислены платёжные поля, добавлена история |
| TC-20 | Повторная отправка | Повторно отправить ту же заявку | Запрос отклонён, так как статус уже не `draft` |
| TC-21 | Изоляция заявок | Клиент A запрашивает заявку клиента B | Доступ запрещён или возвращается 404 согласно реализации |
| TC-22 | История заявки | Запросить `/applications/{id}/history` | События возвращаются в хронологическом порядке согласно контракту |
| TC-23 | Предварительная оценка | Проверить случаи платежа ≤ 40% и > 40% дохода | Результаты соответственно `likely_eligible` и `high_debt_burden` |
| TC-24 | Список staff | Клиент вызывает `/applications/staff` | Доступ запрещён |
| TC-25 | Проверка заявки | Staff вызывает `/check` для `submitted` | Статус меняется на `checking`, пишется история |
| TC-26 | Отклонение | Staff вызывает `/reject` с причиной | Статус `rejected`, причина/комментарий сохранены |
| TC-27 | Пустая причина | Staff отправляет слишком короткую причину отказа | Валидация отклоняет запрос |
| TC-28 | Рекомендации | Создать подбор с допустимыми параметрами | Возвращаются подходящие продукты, баллы и причины |
| TC-29 | Фильтр по сумме/сроку | Подобрать продукт вне допустимого диапазона | Неподходящий продукт отсутствует в выдаче |
| TC-30 | Чужой подбор | Клиент A получает рекомендацию клиента B | Доступ запрещён или 404 согласно реализации |
| TC-31 | OpenAPI | Открыть `/openapi.json` и `/docs` | Спецификация и Swagger UI доступны |
| TC-32 | Миграции | На чистой тестовой БД выполнить `alembic upgrade head` | Схема создаётся без ошибки |


## 4. Автоматические тесты

В описании проекта указано 84 теста. Для подтверждения количества выполните команду из каталога backend:
```powershell
python -m pytest -q
```
Сохраните фактический вывод перед сдачей. Число тестов в документации должно соответствовать реальному результату запуска.
