

Базовый адрес API: `/api/v1`

## 1. Аккаунт и авторизация

| Метод  | Эндпоинт         | Назначение                            |
| ------ | ---------------- | ------------------------------------- |
| `POST` | `/auth/register` | Регистрация пользователя              |
| `POST` | `/auth/login`    | Вход в аккаунт                        |
| `GET`  | `/auth/me`       | Получить данные текущего пользователя |

Регистрация — принимает email и пароль, создаёт аккаунт.

Пример запроса:

```
{
  "email": "owner@example.com",
  "password": "StrongPassword123"
}
```

Вход — проверяет учётные данные и возвращает токен авторизации.

Получение текущего пользователя — возвращает ID и email пользователя, а также другую несекретную информацию об аккаунте.

## 2. Профиль предпринимателя

| Метод | Эндпоинт            | Назначение                           |
| ----- | ------------------- | ------------------------------------ |
| `GET` | `/business-profile` | Получить профиль бизнеса             |
| `PUT` | `/business-profile` | Создать или обновить профиль бизнеса |

В профиле хранятся данные, необходимые для подбора кредита:

- организационная форма: ИП или ООО;
- название бизнеса;
- сфера деятельности;
- дата или срок регистрации бизнеса;
- средняя ежемесячная выручка;
- регион деятельности.

Профиль связан с аккаунтом пользователя. Для MVP достаточно одного основного бизнес-профиля на пользователя.

## 3. Каталог кредитных продуктов

| Метод | Эндпоинт         | Назначение                               |
| ----- | ---------------- | ---------------------------------------- |
| `GET` | `/products`      | Получить список кредитных продуктов      |
| `GET` | `/products/{id}` | Получить подробную информацию о продукте |

Каждый продукт содержит:

- название и описание;
- минимальную и максимальную сумму;
- минимальный и максимальный срок;
- процентную ставку или диапазон ставок;
- требования к бизнесу;
- доступные цели кредитования;
- условия обеспечения, если применимо.

Каталог нужен не только для самостоятельного просмотра: его данные используются алгоритмом рекомендаций.

## 4. Подбор кредитных предложений — ключевая функция

| Метод  | Эндпоинт                | Назначение                                       |
| ------ | ----------------------- | ------------------------------------------------ |
| `POST` | `/recommendations`      | Подобрать предложения по параметрам пользователя |
| `GET`  | `/recommendations/{id}` | Получить сохранённый результат подбора           |

### `POST /recommendations`

Принимает параметры желаемого кредита и, при необходимости, данные бизнеса, ещё не сохранённые в профиле.

Пример запроса:

```
{
  "amount": 1000000,
  "term_months": 24,
  "purpose": "equipment",
  "monthly_revenue": 500000,
  "business_age_months": 24
}
```

Сервер:

1. Получает доступные кредитные продукты.
2. Отбирает предложения, соответствующие сумме, сроку и другим обязательным требованиям.
3. Рассчитывает ориентировочный ежемесячный платёж, если данных для расчёта достаточно.
4. Ранжирует оставшиеся предложения по прозрачным правилам.
5. Возвращает подходящие продукты с объяснением причин рекомендации.

Пример ответа:

```
{
  "recommendations": [
    {
      "product_id": 12,
      "product_name": "Кредит на развитие бизнеса",
      "estimated_monthly_payment": 52000,
      "match_score": 92,
      "reasons": [
        "Запрашиваемая сумма входит в лимит",
        "Доступен выбранный срок",
        "Цель кредита поддерживается"
      ]
    }
  ]
}
```

Здесь `match_score` — демонстрационная оценка соответствия, а не вероятность одобрения банком. Значения в примере условные.

Если ни один продукт не подходит, сервер возвращает пустой список и, по возможности, объясняет, какие ограничения помешали подобрать предложение.

## 5. Оформление кредитной заявки

| Метод   | Эндпоинт                    | Назначение                                   |
| ------- | --------------------------- | -------------------------------------------- |
| `POST`  | `/applications`             | Создать черновик заявки                      |
| `GET`   | `/applications`             | Получить список заявок текущего пользователя |
| `GET`   | `/applications/{id}`        | Получить детали заявки и её статус           |
| `PATCH` | `/applications/{id}`        | Изменить черновик                            |
| `POST`  | `/applications/{id}/submit` | Отправить заявку на обработку                |

При создании заявки пользователь может передать ID выбранного кредитного продукта и параметры кредита.

Пример запроса `POST /applications`:

```
{
  "product_id": 12,
  "amount": 1000000,
  "term_months": 24,
  "purpose": "equipment"
}
```

После создания заявка получает статус `DRAFT`. После отправки сервер проверяет данные и переводит её в `SUBMITTED`.

Пользователь может редактировать черновик, но не должен произвольно менять статус заявки. Сервер также проверяет, что заявка принадлежит авторизованному пользователю.

## 6. Обработка заявки и результат

| Метод | Эндпоинт                      | Назначение                                 |
| ----- | ----------------------------- | ------------------------------------------ |
| `GET` | `/applications/{id}/decision` | Получить результат демонстрационной оценки |
| `GET` | `/applications/{id}/history`  | Получить историю изменения статусов        |

После отправки заявки система может имитировать проверки и демонстрационное принятие решения.

Предлагаемые статусы:

| Статус              | Значение                                        |
| ------------------- | ----------------------------------------------- |
| `DRAFT`             | Черновик                                        |
| `SUBMITTED`         | Заявка отправлена                               |
| `CHECKING`          | Выполняются проверки                            |
| `NEEDS_INFO`        | Требуется дополнительная информация             |
| `APPROVED`          | Положительный результат демонстрационной оценки |
| `REJECTED`          | Отрицательный результат демонстрационной оценки |
| `ALTERNATIVE_OFFER` | Найдено альтернативное предложение              |

Результат оценки может содержать итоговый статус, объяснение решения и альтернативные продукты. В рамках MVP это имитация процесса, а не реальное банковское одобрение.

## 7. Сводная таблица API

| Раздел          | Метод и путь                      | Авторизация |
| --------------- | --------------------------------- | ----------- |
| Аккаунт         | `POST /auth/register`             | Нет         |
| Аккаунт         | `POST /auth/login`                | Нет         |
| Аккаунт         | `GET /auth/me`                    | Да          |
| Профиль бизнеса | `GET /business-profile`           | Да          |
| Профиль бизнеса | `PUT /business-profile`           | Да          |
| Каталог         | `GET /products`                   | Нет         |
| Каталог         | `GET /products/{id}`              | Нет         |
| Подбор          | `POST /recommendations`           | Да          |
| Подбор          | `GET /recommendations/{id}`       | Да          |
| Заявки          | `POST /applications`              | Да          |
| Заявки          | `GET /applications`               | Да          |
| Заявки          | `GET /applications/{id}`          | Да          |
| Заявки          | `PATCH /applications/{id}`        | Да          |
| Заявки          | `POST /applications/{id}/submit`  | Да          |
| Результат       | `GET /applications/{id}/decision` | Да          |
| История         | `GET /applications/{id}/history`  | Да          |

Все защищённые эндпоинты требуют авторизации. Для MVP можно использовать JWT. Пароли хранятся только в виде безопасного хеша, а доступ к профилям и заявкам проверяется на сервере.
