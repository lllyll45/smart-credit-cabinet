# Техническое задание: Frontend Smart Credit Cabinet

## Цель

Разработать пользовательский интерфейс веб-приложения Smart Credit Cabinet с нуля и подключить его к существующему backend на FastAPI.

## 1. Технологии

- React.
- TypeScript.
- Vite.
- React Router для навигации.
- Axios или Fetch API для HTTP-запросов.
- CSS Modules, обычный CSS или существующая UI-библиотека по согласованию.

Перед началом проверить содержимое папки `frontend/`. Если проект ещё не инициализирован, создать приложение в этой папке.

## 2. Страницы

### Регистрация — `/register`
- Форма регистрации с полями, предусмотренными API.
- Проверка обязательных полей.
- Понятные сообщения об ошибках.
- После успешной регистрации предложить перейти ко входу или открыть кабинет, если backend поддерживает автоматическую авторизацию.

### Вход — `/login`
- Форма входа.
- Отправка данных на существующий API авторизации.
- Обработка неверных учётных данных.
- Сохранение токена в соответствии с выбранной схемой авторизации.
- Переход в личный кабинет после успешного входа.

### Личный кабинет — `/dashboard`
- Информация о текущем пользователе, если доступен соответствующий API.
- Список заявок текущего пользователя.
- Статусы заявок.
- Переход к просмотру заявки и подбору кредита.

### Каталог кредитов — `/credits`
- Загрузка продуктов через `GET /api/v1/products`.
- Карточки активных продуктов.
- Ставка, диапазон суммы, диапазон срока и условия.
- Обработка загрузки, пустого результата и ошибок.

### Сравнение кредитов — `/credits/compare`
- Ввод суммы и срока.
- Запрос `POST /api/v1/calculator/compare`.
- Отображение подходящих предложений.
- Ежемесячный платёж, общая сумма выплат, переплата и комиссия.
- Сортировка в соответствии с ответом backend.
- Выбор продукта и переход к оформлению заявки.

### Оформление заявки — `/applications/new`
- Выбранный продукт.
- Сумма и срок.
- Проверка введённых значений.
- Отправка заявки через существующий API создания заявки после согласования формата с backend-разработчиком.
- Отображение ошибок и результата отправки.

### Просмотр заявки — `/applications/:id`
- Информация о заявке.
- Выбранный продукт, сумма и срок, если эти данные возвращает API.
- Текущий статус.
- Доступные действия, соответствующие API.

## 3. Интеграция с backend

Backend работает локально по адресу `http://127.0.0.1:8000`.

Настроить адрес API через переменную окружения Vite, например `VITE_API_BASE_URL`.

Использовать существующие эндпоинты:
- `POST /api/v1/auth/login`
- `GET /api/v1/products`
- `GET /api/v1/products/{product_id}`
- `POST /api/v1/calculator/calculate`
- `POST /api/v1/calculator/compare`
- API заявок — после проверки актуальных схем запросов и ответов.

Регистрация, профиль и создание заявки должны подключаться только к реально существующим эндпоинтам. Если какого-то API пока нет, зафиксировать это как зависимость, а не имитировать успешный ответ.

## 4. Общие требования

- Единый стиль и адаптивная вёрстка.
- Общая навигация.
- Защищённые страницы для авторизованного пользователя.
- Обработка HTTP-ошибок.
- Состояния загрузки и отсутствия данных.
- Разделение компонентов, страниц и API-клиента.
- Не хранить секреты в репозитории.
- Не использовать фиктивные финансовые данные в качестве настоящих предложений банков.
- Проверить сценарий пользователя от входа до создания и просмотра заявки.

## 5. Git

Работать в отдельной ветке `frontend-mvp`, созданной от актуального `main`.

Оформить изменения через Pull Request в `main`. Не включать `.env`, `node_modules` и другие локальные файлы.

Пользователь может зарегистрироваться и войти, открыть каталог, рассчитать и сравнить кредиты, выбрать продукт, отправить заявку и увидеть её в личном кабинете — при условии, что соответствующие backend-эндпоинты реализованы и доступны.

# Smart Credit Cabinet — текущее состояние backend

## 1. Технологический стек

- Python 3.13 — язык разработки.
- FastAPI — REST API.
- PostgreSQL — основная база данных проекта.
- SQLAlchemy — ORM для работы с БД.
- Alembic — миграции структуры базы данных.
- Pydantic — валидация данных запросов и ответов.
- Pytest — автоматическое тестирование.

## 2. Что уже реализовано

1\. База данных и структура проекта

Настроено подключение к PostgreSQL. Созданы модели пользователей, кредитных заявок и кредитных продуктов. Для управления схемой БД используется Alembic, миграция таблицы кредитных продуктов применена.

2\. Авторизация

Реализован эндпоинт `POST /api/v1/auth/login`. По результатам предыдущих проверок он возвращал `200 OK`. Наличие регистрации, получения профиля и полного сценария управления учётной записью пока не подтверждено.

3\. Кредитные заявки

Реализованы операции:

- создание заявки — `POST /api/v1/applications`;
- получение списка заявок — `GET /api/v1/applications`;
- получение заявки по ID — `GET /api/v1/applications/{id}`;
- редактирование заявки — `PATCH /api/v1/applications/{id}`;
- отправка заявки — `POST /api/v1/applications/{id}/submit`.

Эти эндпоинты ранее проверялись и возвращали ожидаемые успешные HTTP-статусы. Ограничение доступа к заявкам конкретного пользователя отдельно не подтверждено.

4\. Каталог кредитных продуктов

Реализованы:

- `GET /api/v1/products` — список активных продуктов;
- `GET /api/v1/products/{product_id}` — получение продукта по ID.

В модели хранятся название, банк, процентная ставка, допустимые суммы и сроки, комиссия, дополнительные условия, активность и временные метки.

Для демонстрации подготовлены три тестовых кредитных предложения Альфа-Банка. Условия являются демонстрационными, не официальными банковскими предложениями.

5\. Калькулятор и сравнение кредитов

Реализованы:

- `POST /api/v1/calculator/calculate` — расчёт выбранного кредита;
- `POST /api/v1/calculator/compare` — сравнение подходящих продуктов.

Калькулятор рассчитывает аннуитетный ежемесячный платёж, общую сумму выплат и переплату. Комиссия учитывается в общей сумме выплат и переплате. Сравнение исключает продукты с неподходящими суммой или сроком и сортирует результаты по общей сумме выплат.

Оба эндпоинта проверены вручную через Swagger и возвращали `200 OK`.

## 3. API, доступное сейчас

| Метод   | Эндпоинт                           | Назначение                 |
| ------- | ---------------------------------- | -------------------------- |
| `GET`   | `/health`                          | Проверка состояния сервиса |
| `POST`  | `/api/v1/auth/login`               | Вход пользователя          |
| `GET`   | `/api/v1/products`                 | Список активных кредитов   |
| `GET`   | `/api/v1/products/{product_id}`    | Детали кредитного продукта |
| `POST`  | `/api/v1/calculator/calculate`     | Расчёт кредита             |
| `POST`  | `/api/v1/calculator/compare`       | Сравнение предложений      |
| `POST`  | `/api/v1/applications`             | Создание заявки            |
| `GET`   | `/api/v1/applications`             | Список заявок              |
| `GET`   | `/api/v1/applications/{id}`        | Детали заявки              |

## 4. Тестирование

На последнем запуске полного набора тестов было 18 успешных тестов:

- 7 тестов расчётной функции;
- 4 теста каталога кредитов;
- 7 тестов API калькулятора.

Тесты каталога и калькулятора используют отдельную SQLite-базу в тестовом окружении, чтобы не изменять рабочие данные PostgreSQL.
