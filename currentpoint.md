Ниже собрала полный статус проекта Smart Credit Cabinet за всё время работы: что мы настроили, что реализовали, что проверили и что ещё нужно сделать до готового хакатонного демо.

# 1. Что представляет собой проект

Smart Credit Cabinet — веб-приложение для подбора кредитных предложений и оформления кредитных заявок.

Пользователь должен иметь возможность сравнить условия кредитных продуктов, выбрать подходящий, заполнить заявку и увидеть результат обработки: одобрение или отказ, ежемесячный платёж, общую сумму выплат и переплату.

Команда состоит из трёх человек: планировали разделить работу так, чтобы два человека занимались бэкендом, один — фронтендом.

# 2. Что мы уже сделали

1\. Подготовили структуру проекта

Готово

Создали репозиторий `smart-credit-cabinet` и основные каталоги:

- `backend/`
- `frontend/`
- `docs/`
- `tests/`

Также предусмотрели README, `.gitignore`, `docker-compose.yml` и документацию по архитектуре.

2\. Настроили бэкенд

Работает

Используем Python и FastAPI. Создали виртуальное окружение, установили зависимости и настроили запуск сервера:

```
uvicorn app.main:app --reload
```

Swagger доступен по адресу `http://127.0.0.1:8000/docs`.

3\. Настроили базу данных

Работает

- PostgreSQL подключён.
- Настроена конфигурация приложения через переменные окружения.
- Подготовлены SQLAlchemy-модели.
- Настроены миграции Alembic.
- Добавлены поля для ролей пользователей, решений по заявкам и результатов расчёта.

4\. Реализовали авторизацию

Проверено

Работает вход пользователя через API. В Swagger мы успешно выполнили `POST /api/v1/auth/login` и использовали Bearer-токен для авторизованных запросов.

5\. Реализовали работу с кредитными продуктами

API работает

Есть API для получения кредитных предложений. При работе с заявкой проверяются активность продукта, допустимая сумма и срок кредита.

6\. Реализовали кредитный калькулятор

Проверено на заявке

Калькулятор использует аннуитетную формулу и `Decimal` для денежных вычислений. Он рассчитывает:

- ежемесячный платёж;
- общую сумму выплат;
- переплату.

7\. Реализовали жизненный цикл кредитной заявки

Основной сценарий работает

Сейчас API поддерживает:

- создание заявки;
- получение списка заявок пользователя;
- получение конкретной заявки;
- изменение черновика;
- отправку заявки на обработку.

При обработке результаты сохраняются в PostgreSQL.

8\. Добавили демонстрационную логику одобрения и отказа

Оба сценария проверены

После отправки заявки бэкенд рассчитывает платёж и сравнивает его с доходом пользователя. Если платёж не превышает 40% дохода, заявка одобряется; иначе отклоняется.

Это демонстрационное правило, не настоящий банковский скоринг.

## 4. Что с тестами

У нас есть тесты для калькулятора, API калькулятора и кредитных продуктов. Также мы проверили основные сценарии через Swagger.

Однако я бы пока не отмечала весь набор автоматических тестов как окончательно пройденный: после последних изменений в `applications.py` нужно ещё раз выполнить полный запуск `pytest`.

Команда из папки `backend`:

```
python -m pytest -q
```

Отдельно стоит исправить предупреждение о deprecated-статусе `HTTP_422_UNPROCESSABLE_ENTITY`, но оно не блокировало проверенные сценарии.

# 7. Приоритет на ближайшее время

Я бы двигалась в таком порядке:

1. Повторно запустить `pytest` и зафиксировать рабочее состояние бэкенда.
2. Подключить фронтенд к уже работающим endpoint'ам — это самый заметный следующий шаг для демо.
3. Реализовать каталог кредитных продуктов, форму заявки и страницу результата.
4. Добавить тесты на ошибки и граничные случаи.
5. Завершить README, `.env.example` и инструкцию запуска для команды.
6. Прогнать демонстрацию целиком на чистом запуске.

Главный итог: бэкенд уже умеет создавать кредитные заявки, рассчитывать платежи и автоматически принимать демонстрационное решение. Основная работа теперь — превратить этот API в удобный пользовательский интерфейс, проверить весь набор тестов и подготовить проект к запуску на компьютерах всех участников команды.
