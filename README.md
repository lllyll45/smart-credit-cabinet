## предполагаемая архитектура в docs/architecture.md
# Ветки
### main
Главная
Стабильная версия всего проекта. Сюда попадает только проверенный код.

### develop/backend-api
Ветка первого бэкенд-разработчика: FastAPI, эндпоинты, бизнес-логика заявок, статусы и демонстрационный скоринг.

### develop/backend-db
Ветка второго бэкенд-разработчика: PostgreSQL, SQLAlchemy-модели, Alembic-миграции и тесты работы с базой.

### develop/frontend
Ветка фронтенд-разработчика: React, TypeScript, страницы, формы и подключение к API.

### Назначение основных директорий

- **`backend/`** — серверная часть приложения. Отвечает за обработку HTTP-запросов, проверку данных, бизнес-логику, работу с базой данных и формирование результатов рассмотрения заявок.
- **`frontend/`** — клиентская часть. Содержит страницы, формы, компоненты интерфейса и код взаимодействия с backend.
- **`docs/`** — техническая документация: архитектура системы, API, модель данных, состояния заявок и тестовые сценарии.
- **`tests/`** — тесты взаимодействия нескольких компонентов и проверка полных пользовательских сценариев. Тесты отдельных модулей backend располагаются в `backend/tests/`.

### Назначение файлов в корне

- **`.env.example`** — пример конфигурации приложения с необходимыми переменными окружения. Секретные значения в него не добавляются.
- **`.gitignore`** — список файлов и директорий, которые Git не должен отслеживать, например виртуальное окружение Python, `node_modules` и локальные файлы `.env`.
- **`docker-compose.yml`** — описание сервисов и их взаимодействия при запуске приложения через Docker Compose.
- **`README.md`** — основная документация репозитория: назначение проекта, используемые технологии, структура и инструкции запуска.


> **Примечание:** это целевая структура проекта. Директории и файлы, которые ещё не созданы, добавляются по мере разработки. Фактическая структура репозитория должна соответствовать текущему состоянию реализации.


### 1. Backend

Требования: Python 3.12 или совместимая версия, поддерживаемая используемыми зависимостями.

Из корневой папки репозитория выполни команды в PowerShell:

```powershell
cd backend

# Создать виртуальное окружение
py -m venv .venv

# Активировать окружение
.\.venv\Scripts\Activate.ps1

# Установить зависимости
pip install -r requirements.txt

# Запустить сервер
uvicorn app.main:app --reload
```

После запуска доступны:

- API: http://127.0.0.1:8000
- Swagger UI: http://127.0.0.1:8000/docs
- OpenAPI-схема: http://127.0.0.1:8000/openapi.json

Чтобы остановить сервер, нажми `Ctrl+C`.

Если PowerShell запрещает активацию виртуального окружения, можно запустить Python из окружения напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

### 2. Frontend

Требования: установленный Node.js и npm.

Открой второй терминал PowerShell в корневой папке репозитория:

```powershell
cd frontend

# Установить зависимости
npm install

# Запустить приложение
npm run dev
```

После запуска Vite выведет локальный адрес приложения в терминале. Обычно это:

http://localhost:5173

Открой этот адрес в браузере. Для остановки нажми `Ctrl+C`.

### 3. Запуск через Docker Compose

В корне проекта предусмотрен файл `docker-compose.yml`. Конфигурация контейнеров находится в разработке, поэтому запуск через Docker Compose доступен после настройки всех необходимых сервисов и Dockerfile.

Когда конфигурация будет готова, запуск выполняется из корня репозитория:

```powershell
docker compose up --build
```

Для остановки контейнеров:

```powershell
docker compose down
```

### 4. Тестирование

Для запуска backend-тестов:

```powershell
cd backend
pytest
```

### 5. Текущее состояние проекта

На начальном этапе подготовлены структура репозитория, документация архитектуры и базовые конфигурационные файлы. Frontend, backend, подключение к базе данных, бизнес-логика и интеграционные тесты развиваются поэтапно.

Инструкции запуска через Docker Compose и тестирования следует актуализировать по мере готовности соответствующих компонентов.
