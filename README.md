# Smart Credit Cabinet — архитектура, план проекта и текущий прогресс

## 1. О проекте

Smart Credit Cabinet — веб-приложение для подбора и сравнения кредитных предложений. Пользователь может зарегистрироваться, войти в личный кабинет, просмотреть кредитные продукты, рассчитать условия кредита, сравнить предложения и подать кредитную заявку.

После отправки заявки система рассчитывает параметры кредита и формирует предварительную оценку на основе соотношения ежемесячного платежа к доходу. Окончательное решение об одобрении или отказе принимает сотрудник банка.

Проект разрабатывается командой из трёх человек: два backend-разработчика и один frontend-разработчик.

## 2. Архитектура приложения

### Backend

Backend реализован на Python с использованием FastAPI. Он отвечает за авторизацию, работу с кредитными продуктами, обработку заявок, расчёты и взаимодействие с базой данных.

Основные компоненты:

- `app/api/` — REST API и обработчики запросов.
- `app/core/` — конфигурация приложения, подключение к базе данных и общие настройки.
- `app/models/` — SQLAlchemy-модели.
- `app/schemas/` — Pydantic-схемы запросов и ответов.
- `app/repositories/` — слой доступа к данным, если соответствующая логика вынесена в репозитории.
- `app/services/` — бизнес-логика, обработка заявок и кредитные расчёты.
- `tests/` — автоматические тесты.
- `alembic/` — миграции структуры базы данных.
- `scripts/` — вспомогательные скрипты, в том числе заполнение каталога демонстрационными продуктами.

Backend доступен локально по адресу `http://127.0.0.1:8000`. Документация API доступна по адресу `http://127.0.0.1:8000/docs`.

### Frontend

Frontend использует React, TypeScript и Vite. Он отвечает за пользовательский интерфейс, формы, личный кабинет, отображение кредитных продуктов и заявок, а также взаимодействие с backend API.

Локальный сервер разработки запускается по адресу `http://localhost:5173`.

Frontend и backend запускаются отдельно. Для взаимодействия между ними настроен CORS.

### База данных

В качестве СУБД используется PostgreSQL. Доступ к данным осуществляется через SQLAlchemy, изменения структуры базы данных оформляются миграциями Alembic.

Основные сущности:

- `User` — пользователь системы.
- `CreditProduct` — кредитный продукт.
- `CreditApplication` — кредитная заявка.

Заявки связаны с пользователями и, при выборе продукта, с соответствующим кредитным предложением.

Настройки подключения и секретные параметры хранятся в локальном `.env`. Этот файл не должен попадать в Git. Для настройки окружения используется `.env.example` без реальных секретов.

## 3. Основные бизнес-процессы

### 3.1. Регистрация и авторизация

1. Пользователь регистрируется.
2. Пароль сохраняется в виде хеша.
3. Пользователь входит в систему и получает JWT-токен.
4. Защищённые эндпоинты используют токен для определения текущего пользователя.
5. Пользователь может просматривать и изменять только собственные черновики заявок.

Для сотрудников банка предусмотрены отдельные ограничения доступа к обработке заявок.

### 3.2. Каталог кредитных продуктов

Система предоставляет список активных кредитных продуктов и подробную информацию о выбранном продукте.

Для продукта предусмотрены название, банк, процентная ставка, допустимый диапазон суммы и срока, комиссии, дополнительные условия и признак активности.

Для демонстрации подготовлены три кредитных продукта.

### 3.3. Расчёт и сравнение кредитов

Кредитный калькулятор рассчитывает:

- ориентировочный ежемесячный аннуитетный платёж;
- общую сумму выплат;
- переплату.

При сравнении система учитывает сумму и срок кредита, рассчитывает стоимость подходящих предложений и сортирует их по общей сумме выплат.

Комиссии учитываются в итоговой стоимости согласно реализованной логике калькулятора. Результат является предварительным расчётом и не гарантирует получение кредита.

### 3.4. Создание и обработка заявки

1. Пользователь выбирает кредитный продукт.
2. Заполняет сумму, срок, цель кредита, ежемесячный доход и занятость.
3. Система создаёт заявку со статусом `draft`.
4. При отправке заявки backend проверяет параметры и рассчитывает кредитные платежи.
5. Система определяет предварительный результат по доле платежа в доходе.
6. Заявка получает статус `submitted` и передаётся сотруднику банка.
7. Сотрудник принимает окончательное решение: одобряет заявку или отклоняет её с указанием причины.

### 3.5. Демонстрационный алгоритм предварительной оценки

Используется правило, основанное на отношении ежемесячного платежа к ежемесячному доходу:

- Если платёж составляет не более 40% дохода, `preliminary_result = "likely_eligible"`.
- Если платёж превышает 40% дохода, `preliminary_result = "high_debt_burden"`.

Это упрощённый демонстрационный алгоритм, а не настоящий банковский скоринг.

Предварительный результат не изменяет статус заявки на `approved` или `rejected`. Окончательное решение принимает сотрудник банка.

## 5. Статусы кредитной заявки

В текущей реализации используются следующие статусы:

| Статус | Значение |
|---|---|
| `draft` | Черновик, который пользователь может редактировать |
| `submitted` | Заявка отправлена и ожидает решения сотрудника |
| `approved` | Заявка одобрена сотрудником |
| `rejected` | Заявка отклонена сотрудником |

Дополнительно поле `preliminary_result` хранит результат демонстрационной оценки: `likely_eligible` или `high_debt_burden`.

Предварительный результат и статус заявки — разные характеристики. Например, заявка со значением `high_debt_burden` всё равно остаётся в статусе `submitted`, пока сотрудник не примет окончательное решение.

## 8. Запуск проекта локально

### Backend

Из корня репозитория:

```powershell
cd backend
```

Активировать виртуальное окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установить зависимости, если окружение новое:

```powershell
pip install -r requirements.txt
```

После настройки `.env` и запуска PostgreSQL выполнить миграции:

```powershell
alembic upgrade head
```

Запустить сервер:

```powershell
uvicorn app.main:app --reload
```

API: `http://127.0.0.1:8000`

Swagger: `http://127.0.0.1:8000/docs`

### Frontend

Во втором терминале:

```powershell
cd frontend
```

Если зависимости ещё не установлены:

```powershell
npm install
```

Запустить сервер разработки:

```powershell
npm run dev
```

Frontend: `http://localhost:5173`

## 9. Ограничения текущей реализации

- Предварительная оценка основана на простом пороге отношения платежа к доходу и не заменяет реальный банковский скоринг.
- Демонстрационные кредитные продукты не являются реальными банковскими предложениями.
- Расчёты не гарантируют одобрения кредита и могут отличаться от условий банка.
- Полный сквозной сценарий через frontend требует отдельной проверки.
- Воспроизводимость запуска на новом компьютере зависит от корректной настройки PostgreSQL, переменных окружения и миграций.
